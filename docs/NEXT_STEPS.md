# 下一步实现计划

## P0：把单片流程升级为可靠任务（最小版本已完成）

已完成任务状态、JSON 持久化、后台 worker、查询、取消、重试、事件日志与 `products/`
产物归档。后续完成以下生产化项：

1. 改用外部队列并在服务重启后恢复未完成任务。
2. 限制输入/输出为素材 ID 或对象存储 URI，禁止生产环境任意本地路径。
3. 验收：10 个并发任务、失败重试、服务重启恢复、产物/日志可追溯。

## P1：闭环窗口候选 → L2 → 剪辑计划（最小版本已完成）

已完成 L0 candidates、L1/L2 记录与 L3 自动计划/渲染串联。后续完成以下质量闭环项：

1. 定义 `ReviewedCandidate`：承载 L0 证据、L2 verdict/confidence、hook、风险标签和最终分数。
2. 为每个 `prompts/*.md` 定义 Pydantic 输出 schema；L2 JSON 解析失败或置信度不足时进入
   `human_review`，不自动渲染。
3. L2 结果回写候选列表，按风格策略重排并自动生成最终 `/v1/clip/plan`。
4. 验收：燃向、快节奏对白、质量异常各准备 20 个窗口的回放集，统计 JSON 合法率、人工
   接受率、Top-3 命中率和平均 L2 成本。

## P2：提升成片质量

1. FFmpeg 渲染加入关键帧附近切点、`loudnorm`、音频淡入淡出和可选 `xfade`。
2. 引入镜头边界、字幕密度、对白/静音与视觉证据作为候选特征。
3. 用人工“选中/拒绝”标注标定 `motion/continuity/luminance` 权重，替换当前固定启发式。
4. 验收：成片时长精度、无音画断裂率、响度达标率、人工可发布率。

## P3：合规、降重与工作台接入

1. 把 L4 标签绑定到候选窗口：命中 block 的窗口剔除，review 转人工，不阻断无风险窗口。
2. 升级降重为双向 pHash/dHash、场景级时间一致性和更可靠的水印识别；阈值基于样本标定。
3. 接入北斗工作台：素材选择 → 批处理任务 → 成片库 → 推广工作台发布。
4. 为 HTTP 服务封装 MCP 工具：创建任务、查询状态、确认候选、渲染、查看产物。

## 执行顺序与依赖

`P0 → P1 → P2 → P3`。P1 的 L2 线上验收需要实际供应商凭据和可访问图像 URL；P2/P3
需要人工标注样本与北斗工作台的素材/成片库接口说明。
