# 风格画像规则库 YAML 设计

> 配套文件：`configs/style_profiles.yaml`（示例规则卡）
> 上游依赖：`docs/signal-layer-design.md`（L0 信号层）
> 状态：设计稿 v1，阈值均为 provisional（6 支样本实测初值）

## 1. 设计目标

1. **配置与代码分离**：新增风格/调阈值不改代码、不重启逻辑，改 YAML 即可；
2. **可审计**：每张规则卡自带标定来源（样本集、日期、状态），生产判定的每个
   结论都能追溯到"哪版规则卡 + 哪批标定样本"；
3. **确定性优先**：L0 信号判定只做阈值查表，模糊地带显式移交 L2（云端 LLM），
   不在规则卡里藏隐式启发式；
4. **与既有契约对齐**：信号字段名与 `SignalValues`（signals-1.0）一一对应；
   钩子分类沿用前贴项目五分类（A 情感冲突 / B 身份反转 / C 视觉张力 /
   D 情绪爆发 / E 悬念前置）；合规门禁对齐 tagging 14 维 Gatekeeper 语义。

## 2. Schema 总览

```text
schema_version        # 规则卡自身格式版本（升级不兼容时升版）
calibration           # 标定元信息：status / sample_set / 日期 / 复标提醒
signal_schema         # 允许引用的信号字段白名单（防拼写错误静默失效）
profiles[]            # 风格规则卡列表
gatekeeper            # 合规门禁查表（L4 消费）
```

### 2.1 calibration 块（规则卡的"出生证明"）

| 字段 | 说明 |
|---|---|
| `status` | `provisional`（试运行）/ `calibrated`（人工签核后可生产）/ `deprecated` |
| `sample_set` | 标定用的信号矩阵文件路径（落盘 JSON，可复现） |
| `sample_count` | 样本数，加载器可校验（< 30 时禁止 status=calibrated） |
| `calibrated_at` / `next_review_at` | 标定日期与复标提醒（每月一次防漂移） |

**加载器硬规则**：`status != calibrated` 的规则卡只能用于试运行/对比输出，
不允许进入生产筛选链路。这是从 Framework holdout 签核机制移植的门禁思想。

### 2.2 conditions（硬判据）

- 语义：`all` = AND，`any` = OR，可嵌套但**一期限制最多两层**，防止规则卡变成
  不可解释的黑盒；
- 每个条件 `{signal, op, value}`，op ∈ `gte/gt/lte/lt/between`；
- `signal` 必须出现在 `signal_schema.fields` 白名单中，加载时校验，未知字段直接
  报错退出（宁可启动失败，不可静默跳过条件）；
- 信号缺失（如无声视频的 `audio_mean_volume_db=null`）时该条件视为**不满足**，
  并在结果 notes 里说明，绝不默认放行。

### 2.3 score_weights（软评分，可选）

硬判据只回答"是不是这个风格"，软评分回答"多典型"：命中后对每个权重信号按
超阈幅度做 min-max 归一化加权，输出 0~1 的 style_score，用于：

- 多风格同时命中时排序展示；
- 批量剪辑时优先处理最典型的素材。

注意量纲：dB 类信号为负值且越大越响，归一化方向在加载器里显式声明，不依赖隐式约定。

### 2.4 hooks + l2_fallback + clip_strategy（下游消费）

| 块 | 消费方 | 作用 |
|---|---|---|
| `hooks` | L2 prompt 组装 | 该风格优先寻找的钩子类型（五分类），决定理解 prompt 的侧重 |
| `l2_fallback` | L2 编排 | `trigger`：`always`（一期信号不足必送）/ `ambiguous_multi_hit`（多命中才送）；`max_windows` 限制送检窗口数控成本 |
| `clip_strategy` | L3 剪辑 | 目标时长（15s）、片段偏好、最小片段时长等剪辑提示 |

### 2.5 gatekeeper（合规门禁）

- 只做**确定性查表**：`block`（自动拦截）/ `review`（转人审）两级；
- 标签来源是 tagging 14 维合规输出或 LLM 打标，规则卡不自行判断"轻微血腥"
  这类模糊语义——模糊判断永远在打标侧完成，门禁侧只查表，保证可审计；
- 与客户需求对齐：轻微血腥暴力片段默认 `review`，不自动进成片。

## 3. 版本与演进策略

- 新增信号：先在 `SignalValues` 升 schema_version，再进 `signal_schema.fields`，
  最后才允许出现在 conditions——三步顺序不可颠倒；
- 规则卡文件随代码仓库版本管理；每次阈值变更必须同步更新 `calibration` 块
  并把旧矩阵文件留在 `docs/calibration/` 归档（现有 v0/v1 即先例）；
- 二期信号（特写占比/台词密度/BPM）落地后，燃向/伤感/分析类规则卡各自升一版，
  老版本保留为回退基线。

## 4. 样本集准备的必要性

### 4.1 为什么必须准备

1. **本轮实测已证明阈值无法凭空设定**：6 支真实短剧全部快节奏
   （mean_motion 0.28~0.50、cut_rate 17.5~27.9/min），此前设计文档的示例阈值
   （motion ≥ 0.12）在真实分布下会把**所有素材**判成燃向——没有样本，
   阈值就是拍脑袋，规则卡必然系统性偏科；
2. **只有正样本定不出下界**：伤感/分析类的判据是"低运动、低切点、高特写"，
   这些是**下界阈值**，必须由慢节奏负样本标定。本批样本完全没有覆盖，
   伤感规则卡只能 `enabled: false` 禁用；
3. **风格边界靠重叠区定义**：本批里 2918（cut_rate 27.9 但 motion 仅 0.36）
   这类"快切但低运动"样本，正是区分燃向与快节奏对白的边界案例。样本集里
   这类边界样本的比例直接决定规则卡的分辨力；
4. **回归基线与签核机制**：标定矩阵落盘后成为回归测试基线——后续任何代码/
   阈值改动都要在样本集上复跑对比，防止静默劣化（Framework holdout 签核同思路）；
5. **对抗内容漂移**：短剧题材更新快，上季度标定的阈值可能下季度失准。
   样本集 + 每月复标是持续运营的一部分，不是一次性成本。

### 4.2 样本集怎么准备

**规模与配比**（一期最小可行）：

| 类别 | 数量 | 说明 |
|---|---|---|
| 燃向 | ≥ 10 | 战斗/特效/快移；含 2~3 支边界案例（特效多但整体节奏不快） |
| 伤感 | ≥ 10 | 特写多/慢节奏；含对白哭戏与空镜慢推两类 |
| 分析类/解说 | ≥ 10 | 口播/信息直给；含纯口播与图文混剪 |
| 其他/干扰项 | ≥ 5 | 片头合集、广告、纯 BGM 卡点等，验证规则卡不会乱命中 |
| 合计 | 35~50 | |

**标注字段**（每支样本一行，建议 CSV/JSON 与视频同目录）：

```csv
video_id, file_name, style_label, hook_types, compliance_flags, expected_highlight_ranges, annotator, annotated_at
```

- `style_label`：单选（燃向/伤感/分析类/其他），拿不准就标"其他"，不要硬归类；
- `hook_types`：五分类多选，供 L2 prompt 标定使用；
- `compliance_flags`：是否含轻微血腥/暴力/敏感内容（供 gatekeeper 标定）；
- `expected_highlight_ranges`：人工认为的高光时间段（供 L3 剪辑评估，一期可选）。

**操作流程**：

1. 从客户素材库按剧目分层抽样（避免单一剧目风格垄断）；
2. 人工标注（建议双人标注 + 分歧仲裁，风格主观性决定了需要一致性校验）；
3. 批量调 `/v1/signals/compute` 落盘信号矩阵（沿用 `docs/calibration/` 惯例）；
4. 按风格分组画分布（箱线图），取分位数定阈值，写回规则卡并置
   `status: calibrated`；
5. 矩阵 + 标注表入版本库，成为回归基线。

### 4.3 不准备样本集的代价（决策参考）

- 规则卡只能永远 `provisional`，筛选结论不可承诺给客户；
- "一键筛选"退化为"一键粗筛 + 全量人工复核"，违背产品目标；
- 阈值改动无回归依据，任何调整都是盲改，线上事故无法定位。

## 5. 下一步

1. 向客户/运营申请 35~50 支分层抽样素材与标注排期；
2. 实现规则卡加载器（YAML 解析 + 白名单校验 + status 门禁 + 信号求值），
   附单元测试；
3. 样本到位后走 §4.2 流程完成首轮正式标定，规则卡置 `calibrated`。
